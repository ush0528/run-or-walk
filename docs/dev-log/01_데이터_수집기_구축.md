> 기간: 2026. 11. 20.(금) ~ 11. 23.(월) 새벽
> 목표: 2026. 11. 23. 06:00부터 부산 BIMS 버스 도착 정보를 4개월(~2027. 3. 31.) 동안 자동 수집

## 1. 공공데이터 이용 허가

### 1-1. 사용하는 API (부산광역시_부산버스정보시스템)

| 상세기능 | 하는 일 | 연구에서 쓰는 곳 |
|---|---|---|
| `busStopList` | 정류소 이름 → 정류소 번호(bstopid)·위치 | 수집 정류소 고르기 |
| `stopArrByBstopid` | 정류소에 곧 도착할 버스, 남은 시간·정류장 수 | 도착 예정 시간의 오차 계산 |
| `busInfoByRouteId` | 노선의 모든 버스의 현재 위치 | 버스가 정류장을 **실제로 출발한 시각** 판정 |

그 밖에 `busInfo`, `busStopArrByBstopidLineid`, `bitArrByArsno`도 신청되어 있으나 사용하지 않음.

### 1-2. 호출 한도 문제와 운영계정

| 항목 | 값 |
|---|---|
| 개발계정 한도 | 상세기능별 하루 10,000회 |
| 필요한 호출 수 | 정류소 10곳 × 15초 간격 × 17시간(06~23시) = 하루 약 40,800회 |
| 개발계정으로 가능한 간격 | 약 60초 (실제 출발 시각을 판정하기에 너무 김) |

**시행착오: "폰을 한 대 더 쓰면 되나?"**
- 처음에는 기기를 늘리면 한도가 늘어난다고 생각함.
- 한도는 **기기가 아니라 인증키(계정)**에 걸려 있음. 같은 키로 폰 두 대를 쓰면 한도를 더 빨리 씀.
- 해결책 후보: ① 운영계정 신청 ② 팀원 계정의 키를 추가해 정류소를 나눔 ③ 간격을 늘림 → ①을 선택.
- 이 과정에서 수집기가 **키를 여러 개** 쓸 수 있게 하고, **한도에 맞춰 간격을 자동 계산**하도록 고침.

**운영계정 신청**
- 활용사례 등록이 필요함: 서비스 URL, 서비스 설명, 기능 및 화면, 캡처, 대표 이미지, 개발자 유형·소재지, 서비스 개시일.
- 서비스가 아직 없어서 **GitHub 저장소를 만들어 서비스 URL로 제출**. 서비스 설명에는 "개발 중인 연구 프로젝트"라고 정직하게 적음.
- 캡처: 계획서의 앱 화면 설계안과 서비스 흐름도. 대표 이미지: 248×93px 썸네일을 새로 만듦.
- 결과: **자동 승인**, 상세기능별 하루 **100,000회**, 활용기간 2026-11-20 ~ 2028-11-20.

## 3. 수집 프로그램 (collector/bims_collector.py)

파이썬 기본 기능만 사용 (추가 설치 없음).

| 명령 | 하는 일 |
|---|---|
| `find 이름` | 정류소 번호 찾기 |
| `test` | 정류소마다 한 번 호출, 응답 건수와 자동 간격 확인 |
| `plan` | 한도에 맞는 간격만 계산 |
| `run` | 수집 시작 (06~23시만 호출, 나머지 시간은 대기) |
| `status` | 오늘 호출 수, 마지막 수집 시각, 파일 크기 |
| `backup` | 지난 날짜 자료를 지금 바로 Google Drive로 |

### 3-1. 동작 원리

| 기능 | 내용 |
|---|---|
| 원본 그대로 저장 | 응답을 가공하지 않고 조회 시각과 함께 한 줄씩(JSON Lines) 저장. 나중에 분석 방법이 바뀌어도 다시 계산 가능 |
| 자동 간격 | (남은 호출 수, 남은 시간)으로 간격을 계속 다시 계산. 최소 15초. 한도 때문에 하루 중간에 수집이 끊기지 않음 |
| 버스 위치 노선 자동 수집 | 도착 정보 응답에 나온 노선 번호(lineid)를 모아 그 노선들의 버스 위치를 조회 |
| 오류 처리 | 네트워크 오류는 `_errors.jsonl`에 기록하고 다음 차례에 다시 시도. 프로그램은 멈추지 않음 |
| 압축·백업 | 날짜가 바뀌면 전날 파일을 .gz로 압축 → rclone으로 Google Drive에 복사 |

## 4. 폰을 수집기로 만들기 (Termux)

### 4-1. Termux 설치

**Termux**: 안드로이드에서 리눅스 명령어를 쓰게 해 주는 앱. 폰을 "화면 없는 작은 컴퓨터"처럼 쓸 수 있음.

**시행착오**
- Play 스토어 버전은 업데이트가 끊겨 패키지 설치 오류가 날 수 있음 → 공식 배포처 사용.
- "F-Droid에서 개발자 Fredrik Fornwall인 Termux를 찾으라"고 안내했으나, **F-Droid 화면에는 개발자 이름이 표시되지 않아** 찾지 못함.
- 해결: 웹브라우저로 `f-droid.org/packages/com.termux` 접속 → **Download APK**로 Termux만 직접 설치 (F-Droid 앱은 설치하지 않음).

### 4-2. 기본 설정 명령

| 명령 | 뜻 |
|---|---|
| `pkg update && pkg upgrade -y` | 설치 도구(pkg)의 목록을 새로 받고 설치된 프로그램을 최신으로 |
| `pkg install python -y` | 파이썬 설치 (Python 3.14.10) |
| `termux-setup-storage` | Termux가 폰 저장공간(내 파일)에 접근하도록 허락 |

**시행착오: 업데이트가 4%에서 멈춤**
- 원인은 멈춘 것이 아니라 **설정 파일(openssl.cnf)을 새 버전으로 바꿀지 묻는 질문**이 화면에 떠 있었던 것.
- 저장소 서버를 바꾸는 명령(`termux-change-repo`)을 그 질문 칸에 입력해 버림 → 같은 질문이 다시 나옴.
- 해결: **Y** 입력 후 Enter → 업데이트 계속 진행.
- 교훈: 진행이 멈추면 화면 끝에 질문(`[Y/n]`, `[default=N]`)이 있는지 먼저 확인.

### 4-3. 프로그램 넣기

**시행착오 1: 받은 파일을 Termux가 못 찾음**
- 대화창에서 받은 파일이 폰의 '내 파일'에는 보이지만 `cp ~/storage/downloads/bims_collector.py ~/` 실패, `find`로도 안 나옴.
- 원인: 파일이 **다운로드 폴더가 아닌 앱 전용 폴더**에 저장되어 다른 앱(Termux)이 접근할 수 없음.
- 해결: **GitHub에서 직접 내려받기**로 변경.

```
curl -L -o bims_collector.py https://raw.githubusercontent.com/ush0528/run-or-walk/<판번호>/collector/bims_collector.py
echo '{"A": "<인증키>"}' > keys.local.json
curl -L -o stops.json https://raw.githubusercontent.com/ush0528/run-or-walk/<판번호>/collector/stops.json
```

**시행착오 2: 새로 올렸는데 예전 판이 내려옴**
- `main` 주소로 받았더니 `test`에서 "STOPS가 비어 있습니다" → 받은 파일 크기가 예전 판(11,423 B)과 같았음.
- 원인: raw.githubusercontent.com은 몇 분 동안 **예전 파일을 캐시**해서 보내 줌.
- 해결: 주소에 `main` 대신 **커밋 번호**를 넣어 정확한 판을 받음. 받은 뒤 **파일 크기**로 판을 확인 (`wc -c bims_collector.py`).

### 4-4. 정류소 선정

`find`로 후보를 찾고 위치(위도·경도)와 정류소 고유번호(arsno)를 보고 결정.

| 구분 | 정류소 | bstopid | 근거 |
|---|---|---|---|
| A 진구 | 성곡시장입구 | 171690303 | 연구자 거주지 정류장 (필수) |
| A 진구 | 성곡시장 (반대 방향) | 171690304 | 고유번호 05046·05047이 연속 → 길 양쪽 한 쌍 |
| A 해운대 | 운촌 1, 2 | 504990000, 504980000 | 같은 이름 2개 = 양방향 |
| B 진구 후보 | 서면교차로, 서면,광무교 | 506980000, 164670201 | 중앙대로 구간 |
| C 진구 | 서면역.롯데호텔백화점 | 164630302 | 서면 대형 환승 정류장 |
| B 해운대 후보 | 센텀시티역.벡스코 1, 2 | 185130101, 185100201 | 해운대로 구간 |
| C 해운대 | 신세계센텀시티 | 185220101 | 백화점 앞 길가 |

**결정 과정에서의 판단**
- 처음에는 A만으로 먼저 시작하고 B·C는 다음 날 정하자고 제안했으나, 사용자가 **당일 B·C까지 확정**하기로 결정.
- 작업 환경에서 BIMS API에 직접 접속할 수 없어(네트워크 차단), 사용자가 폰에서 `find`한 결과 화면을 보고 결정.
- 위치 숫자만으로는 도로 **한가운데(중앙버스전용차로)**인지 **길가**인지 확실히 구분할 수 없음 → 한도가 넉넉하므로 **B 후보를 2개씩 모두 수집**하고, 분석 전에 지도로 확인해 고르기로 함.
- `find 해운대역`은 멀리 떨어진 동해선 신해운대역만 나와서, 해운대 C를 신세계센텀시티로 변경.
- 결과: 10곳, 하루 약 40,800회 (한도의 41%).

### 4-5. 시험과 실행

| 명령 | 결과 |
|---|---|
| `python bims_collector.py test` | 10곳 모두 HTTP 200, 버스 위치 정상, 간격 15초 |
| `termux-wake-lock` | 화면이 꺼져도 Termux가 잠들지 않게 함 |
| `python bims_collector.py run` | 06시까지 대기 후 자동 수집 |
| CTRL+C | 수집기 멈춤 (새 판으로 바꿀 때). `KeyboardInterrupt` 메시지는 정상 |

**폰 설정**: Termux 배터리 '제한 없음', 자동 재시작·자동 업데이트 끄기, 배터리 보호 켜기, 충전기 연결, Wi-Fi 근처.

**시행착오 3: 공폰이라 Wi-Fi만 쓸 수 있음**
- Wi-Fi만으로 충분함. 끊기면 그동안의 자료만 빠지고 프로그램은 다음 차례에 자동으로 다시 시도.

**시행착오 4: 버스 위치 자료 용량**
- `busInfoByRouteId` 응답에는 **노선의 모든 정류장 줄**(예: 145줄)이 들어 있음. 버스가 없는 정류장 줄이 대부분.
- 그대로 저장하면 하루 약 4GB 이상 → 4개월이면 폰 저장공간 부족 예상.
- 해결: **차량번호(carno)가 있는 줄만** 저장하고, 원래 줄 수(n_items)는 따로 기록. 출발 판정에 필요한 정보는 유지, 용량 약 1/10.

## 5. Google Drive 자동 백업

### 5-1. 개념

| 용어 | 설명 |
|---|---|
| rclone | 파일을 클라우드 저장소로 복사하는 프로그램 |
| OAuth | 비밀번호를 넘기지 않고 "이 앱에 내 드라이브 접근을 허락"하는 방식 |
| OAuth 클라이언트 (client_id, client_secret) | 구글에 "이 앱이 누구인지" 밝히는 신분 정보 |
| token (access/refresh) | 로그인·허락 후 받는 출입증. **이것만 있으면 드라이브에 접근 가능** |

**왜 MCP 연결로는 안 되나:** MCP로 Google Drive를 연결하면 Claude가 드라이브를 쓸 수 있지만, 수집 자료는 **폰 안**에 있고 Claude는 폰에 접근할 수 없음. 그래서 업로드는 폰이 직접 해야 함.

### 5-2. 진행 과정과 시행착오

**① rclone 공용 ID로 연결**
```
pkg install rclone -y
rclone config      # n → 이름 gdrive → drive → client_id 비움 → scope 1 → 브라우저 로그인
```
- 경고: "rclone의 공용 client_id는 2026년 중 중단 예정" → 수집 기간 중 백업이 끊길 위험.
- **사고: 설정 완료 화면을 캡처해 공유함 → 화면에 token이 노출됨.**

**② 전용 OAuth 클라이언트 만들기 (Google Cloud)**

| 순서 | 한 일 | 시행착오 |
|---|---|---|
| 1 | console.cloud.google.com 접속 | **"무료 체험 $300, 카드 등록"** 화면이 먼저 뜸 → 이것은 체험 가입이라 필요 없음. 닫고 `console.cloud.google.com/projectcreate`로 직접 이동 |
| 2 | 프로젝트 **BIMS-backup** 생성 | 홈 화면에 API 카드가 많아 혼란 → 필요한 것은 Drive API 하나뿐 |
| 3 | Google Drive API 사용 설정 | 결제 요구 없음 |
| 4 | OAuth 동의 화면(브랜딩): 앱 이름, 지원 이메일, 외부 대상 | |
| 5 | **앱 게시** (테스트 → 프로덕션) | 버튼이 비활성: "홈페이지 URL, 개인정보처리방침 URL 필요" → GitHub 저장소 주소와 `PRIVACY.md`를 새로 만들어 입력 |
| 6 | 클라이언트 만들기: **데스크톱 앱** | |

게시하지 않고 '테스트' 상태로 두면 refresh token이 **7일마다 만료**되어 백업이 멈춤.

**③ 폰에서 전용 클라이언트로 다시 연결**
```
rclone config      # e → gdrive → client_id·secret 입력 → token 새로 받기
```
- 브라우저에 "Google에서 확인하지 않은 앱" 경고 → 처음에는 **"안전한 환경으로 돌아가기"**를 눌러 로그인 취소됨.
- 해결: 다시 열고 왼쪽 아래 **고급 → bims-backup(으)로 이동** → 허용. (직접 만든 앱이라 심사를 안 받았을 뿐이며, 개발자 이메일이 본인 것인지 확인)
- 확인: `rclone lsd gdrive:` → 드라이브 폴더 목록 출력.

**④ 노출된 token 무효화**
- myaccount.google.com/permissions → **rclone(공용 앱, 웹 주소 rclone.org)** → 모든 액세스 권한 삭제.
- 새 연결(bims-backup)은 유지.

### 5-3. 백업 동작

| 시점 | 동작 |
|---|---|
| 날짜가 바뀐 뒤 수집기의 첫 반복 | 전날 `.jsonl` → `.jsonl.gz` 압축 |
| 이어서 | `rclone copy 내장저장공간/BIMS/날짜 gdrive:뛸까말까_BIMS/날짜` |
| 성공 | 폴더에 `_backup_ok` 표시 → 다시 올리지 않음 |
| 실패 | `_log.txt`에 "백업 실패" 기록, 다음 날 재시도. 수집은 계속 |

## 6. 보안 사고와 대응 기록

| 사고 | 원인 | 대응 |
|---|---|---|
| BIMS 인증키를 대화창에 입력 | 설정 정보를 공유하면서 함께 붙여 넣음 | 저장소에는 넣지 않음. 계획서에 대화 공유 링크가 있어 노출 가능성 → 필요 시 공공데이터포털에서 재발급 |
| Google token 노출 | rclone 설정 완료 화면 캡처 | 공용 rclone 앱 권한 삭제로 무효화 |
| client_secret 일부 노출 | 재설정 화면 캡처 | 데스크톱 앱용이라 단독으로는 위험 낮음. 필요하면 Google Cloud에서 재설정 |

**교훈:** `rclone config` 완료 화면, 인증키, 클라이언트 비밀번호는 캡처·공유하지 않는다.

## 9. 발표에 쓸 수 있는 포인트

- **"한도는 기기가 아니라 계정에 걸린다"**: 처음의 오해와 운영계정 신청으로 해결한 과정.
